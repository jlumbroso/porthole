# Words for the model-facing surface

- **Date**: 2026-10-13
- **Iteration**: 1
- **Status**: Draft
- **Deciders**: Jérémie Lumbroso (human), advised by the naming review; Glazier 5.5 (Claude Opus 5.5)

**TL;DR**: Before the outside interface ships, settle four sets of words — what to call the window, the verbs, the link's shape, and the name of the text tab — because they become part of other people's scripts and cannot be changed afterwards without breaking them.

---

**Source**: `Seed: docs/adr/seed-2026-10-13-porthole-for-models.md` (Purser: the verbs, parameters and settings "fossilize the way the setting key `useInternalApi` nearly did"), and Jérémie's note answering QST-CYCLE-REPRO in ADR-0010, verbatim: *"We should distinguish terms a bit more, like 'editor code tab' vs 'floating window' — you should use 'floating window' consistently to refer to the window generated by Porthole."*

## Questions

### QST-TERM-WINDOW: What do we call the window porthole opens, when other floating windows exist too?
- Status: unanswered
- Why asking: "Floating window" is also VS Code's name for any editor moved into its own window. Once models can list and act on windows, the words must say which floating windows are porthole's. You asked for "floating window" to be used consistently for porthole's.
- Need: pick a letter (or override — any shape answers)

Options:
- **A — "floating window" alone**: always means porthole's in porthole's own text; VS Code's others are "other floating windows" when they need mentioning.
- **B — "Porthole window"**: the product name as a qualifier ("list Porthole windows", "a Porthole window shows tasks.html"); "floating window" stays the general VS Code term.
- **C — "a porthole"** (lowercase common noun): "open a porthole", "list portholes".

**Recommendation**: (by Glazier 5.5, Claude Opus 5.5, 2026-10-13)

**A — "floating window" alone, as you asked.** *Rationale*: it is your stated preference and the naming review's earlier ruling; within porthole's commands and documents there is no other kind to confuse it with, and a model's list only ever contains porthole's. *Confidence*: 0.6 — because once a skill sits beside VS Code's own vocabulary, a model may need "Porthole's floating window" to say which; that is the naming review's call. *If wrong*: if the review finds the general term ambiguous in model-facing text, B.

### QST-TERM-VERBS: What are the verbs called?
- Status: unanswered
- Why asking: They become link paths, command names and words in the skill, all permanent once used.
- Need: pick a letter (or override — any shape answers)

Options:
- **A — plain verbs**: `open`, `list`, `refresh`, `focus`, `resize`, `pin`, `unpin`, `dock`, `close`.
- **B — the words already shown in porthole's menus**: `pop-out`, `cycle-size`, `toggle-pin`, `dock-back`, plus `list`, `refresh`, `close`.
- **C — browser words**: `show`, `list`, `reload`, `raise`, `resize`, `pin`, `unpin`, `dock`, `close`.

**Recommendation**: (by Glazier 5.5, Claude Opus 5.5, 2026-10-13)

**A — plain verbs.** *Rationale*: a model guesses `open` before `pop-out`; Sounder asks for explicit desired states rather than toggles, and B's `toggle-pin` and `cycle-size` are toggles; and "refresh" is your word from the seed. *Confidence*: 0.55 — because the menus and the verbs would then use different words for the same action, which the review may weigh differently. *If wrong*: if one vocabulary across menus and links matters more, B, with `pin`/`unpin` replacing `toggle-pin`.

### QST-TERM-LINK: What does the link look like?
- Status: unanswered
- Why asking: Every script and skill will build this string. The parameter names and the version marker are as permanent as the verbs.
- Need: pick a letter (or override — any shape answers)

Options:
- **A — the brief's shape**: `vscode://jlumbroso.porthole/open?path=/abs/tasks.html&w=420&h=640`
- **B — versioned, with named sizes**: `vscode://jlumbroso.porthole/v1/open?file=/abs/tasks.html&size=S` (or `width=…&height=…`)
- **C — versioned in a parameter**: `vscode://jlumbroso.porthole/open?v=1&file=/abs/tasks.html&width=420&height=640`

**Recommendation**: (by Glazier 5.5, Claude Opus 5.5, 2026-10-13)

**C — version as a parameter, full words.** *Rationale*: Purser asked for a version marker; a parameter keeps one path per verb, so old links without `v` can still be read as version 1; `file` and `width`/`height` read better to a model than `path`, `w`, `h`. *Confidence*: 0.55 — because a path segment (B) is the more common convention in web APIs, and the review may prefer it. *If wrong*: B.

### QST-TERM-SOURCE: What do we call the ordinary editor tab that shows the file's source?
- Status: unanswered
- Why asking: You asked us to distinguish it from the floating window. Instructions and logs keep needing to say "open the file as text first" or "VS Code opened it as text".
- Need: pick a letter (or override — any shape answers)

Options:
- **A — "the text editor"**: VS Code's own term.
- **B — "the source tab"**: names what it shows, as against the rendered page.
- **C — "the code tab"**: your phrase, "editor code tab".

**Recommendation**: (by Glazier 5.5, Claude Opus 5.5, 2026-10-13)

**B — "the source tab".** *Rationale*: the distinction that matters is source versus rendered page; "text editor" is accurate but users of VS Code rarely say it; "code tab" is natural for HTML but odd for a Markdown plan. *Confidence*: 0.5 — because this is a matter of ear, which is the review's. *If wrong*: whichever the review prefers.
