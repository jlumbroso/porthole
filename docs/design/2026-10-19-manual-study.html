01 / Getting started

Your first floating window.

Keep a checklist, a set of instructions, or a local report beside the work. Start with a file you already have.

01 Open a local file.

In VS Code, open an HTML or Markdown file. Porthole shows its rendered contents in a separate window.

If you haven’t installed Porthole, search for Porthole in the Extensions view, or run:

code --install-extension jlumbroso.porthole

02 Pop it out.

With the file open, press Ctrl + Alt + M (⌃⌥M on macOS). You can also right-click the file in the Explorer and choose Pop Out to Floating Window.

The rendered page opens in a compact, pinned window. Tabs, breadcrumbs, and the status bar disappear; the window’s title bar remains.

03 Keep working.

Switch to the editor or another application. With always-on-top enabled, the page stays in view. Edit the source file and its rendered view updates.

A Markdown checkbox is a preview.Markdown task-list boxes are shown, but you cannot click them to change the file. For an interactive checklist, use an HTML page.

04 Put it back.

Focus the floating window and press the same shortcut, or run Porthole: Dock Back into Main Window.

To adjust the window while it floats, use Porthole: Cycle Window Size or Porthole: Toggle Always on Top.

02 / Terminal & agent reference · Experimental

Open a page from a terminal.

Write the page to disk. Send its local path to VS Code. Let the person working see the result.

The smallest useful example.

On macOS, replace the example path with the absolute path to an existing local HTML file, then run:

macOS shell · replace the path
open 'vscode://jlumbroso.porthole/v1/open?file=/absolute/path/tasks.html&width=420&height=640'

Keep the quotes: the shell must leave the & characters alone. Encode each path segment, preserving the separating slashes; in JavaScript, use path.split('/').map(encodeURIComponent).join('/').

One current limit: a filename containing & followed by letters and = cannot be sent through this link, even encoded. Rename that file before using the interface.

What the link means.

Parameters for /v1/open
ParameterMeaning
fileRequired. A local path, absolute or relative to a workspace folder in the receiving VS Code window.
width
height		Both or neither, in pixels. Omit both to use the first size preset.
repoA workspace folder’s name, used to disambiguate a relative path. It is not a repository URL.

What the person sees.

The VS Code window used most recently receives the link. An allowed file opens in a floating window; a file outside the allowed folders prompts for Open Once, Allow This Folder, or Cancel. VS Code may also ask permission to route the first link to Porthole.

Opening a window takes the keyboard.On macOS, a new floating window takes focus. An agent should account for the person typing elsewhere before sending a link.

Check the result.

Sending a link does not prove that a page became visible. If it is refused, Porthole explains why in a message and the Porthole output channel. When reporting what happened, distinguish sending the link from observing the window.

Update the page by editing its file. Send the link again to bring the existing window forward; supplying a size reopens the page at that size.

Teach an agent the same interface.

Run Porthole: Install the Skill for Models in This Project. It writes the skill into .claude/skills/porthole/SKILL.md in a workspace folder, where Claude Code can find it. Other agents can read the same file explicitly.

The larger proposal: a little manual for a well-made instrument

A small, useful book.

The product page makes the introduction. The manual stays beside someone learning or working. Begin with the first successful action, then grow where real use creates questions.

  • Your first window
  • Working with HTML and Markdown
  • Size, position, pinning, and docking
  • Opening from a terminal or agent
  • Settings, permissions, and troubleshooting

Paper, glass, and type.

Keep Porthole’s existing warm paper, muted green, brass accents, and logo. Jérémie chose Berkeley Mono for chapter and section titles as well as commands and small labels, with sans-serif paragraphs. The serif comparison remains available above.

Give screenshots room to explain. Let the ordinary chapter page carry the identity. A narrow reading column should remain useful at the size of a Porthole window.

One source of truth.

Jérémie chose a separate porthole-docs repo, initially private and founded from Human-SI Collaboration Template A. Keep commands and setting definitions tied to an extension release; explain behavior in shared source text so HTML and model-readable output agree.

No Meta tooling. This study is handwritten HTML, CSS, and browser-native JavaScript. Generator choice, font web-use rights, and publication remain open.
