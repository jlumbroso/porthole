A reference or an interactive page.

Porthole renders neither format itself. It brings VS Code’s existing renderer into a floating window.

Write an HTML page for a small window.

Give it a useful title, such as:

<title>[my-project] Release checklist</title>

VS Code shows the page’s title in the floating window. A project name helps distinguish several pages at a glance.

Keep the page readable at about 420–640 pixels wide. Let paragraphs wrap, keep buttons large enough to use, and make long commands scroll within their own block.

A page can use its own localStorage to remember checklist state when the same file is reopened. The page supplies that behavior; Porthole does not add it.

Choose Markdown colors.

porthole.markdown.colorScheme accepts three values:

  • auto follows VS Code’s theme. This is the default.
  • light gives the Markdown page light colors.
  • dark gives it dark colors.

The colors follow the file. While it is popped out, every preview of that file uses the chosen scheme, including a preview docked in the main window. Previews of other files keep following VS Code’s theme. Code blocks retain VS Code’s syntax colors.

Need a checklist you can tick? Markdown task-list boxes are read-only in the preview. Use HTML when the person following the steps needs to click, type, or press a button.

Start from the local file.

Porthole opens local HTML and Markdown files. It does not yet pop out a page already open in a browser tab, a web address, or a localhost URL. Remote and virtual workspaces are outside the supported scope.

To bring a page forward again, pop out the same file. Porthole finds its existing floating window instead of opening another.
