## Summary

### (a) Best candidates for the README hero / gallery
1. **#24 (7.37.57)**: clean, window-only, legible; shows the "Pop Out to Mini Window ^⌥M" menu entry. Best for a "how to trigger it" gallery image. Almost no privacy issue.
2. **#16 (7.11.38)** (and its interactive sibling **#17**, 7.12.04): the compact floating page window above code in the dev-host editor, the core value ("a small floating window showing only the rendered page"). Crop out the menu bar and the main window behind. Remaining flag: truncated `/Users/jlumbroso` in the floating window's URL bar.
3. **#22 (7.32.07)**: code on one side, small page window on the other. Reads as "page beside code", the closest to the product promise. Crop to the dev-host window. Same URL-bar caveat.
4. **#13 (7.11.09)**: shows the command set (Pop Out / Dock Back / Cycle Mini Window Size / Toggle Always on Top, with the keybinding). Crop tightly to the floating window + palette.
5. **#2 (3.59.16)**: a standalone small window with nothing else on screen. Good as a tiny inset, but the toolbar URL shows the username path; retake with a neutral path if used as a hero.

For a polished listing, a retake with the installed (non-dev-host) extension in a neutral folder would be better than any of these: the title bar still says "[Extension Development Host]" in almost every image and the toolbar URL always carries `/Users/jlumbroso/...`.

### (b) Privacy flags that cropping cannot fix
- The `/Users/jlumbroso/Programming/porthole/...` path (username + full home directory) is inside the window frame in **#6, #7, #8** (title bar and URL bar), **#18** (breadcrumb, URL, title), and **#21** (title bar and URL). Cropping only works if the toolbar/title is cut away, which defeats the shot. The truncated `file:///Users/jlumbroso/Programming...` URL in the small floating window remains in **#2, #3, #12, #13, #16, #17, #22, #23** even after a crop to the window.
- **#9** (terminal with agent sessions, inbox filenames, internal workflow) and **#14/#15** (command palette listing the author's other extensions) are full-content issues, not croppable: they are not listing material anyway.
- Everywhere the macOS status bar shows a time-tracker duration ("15/17/18 hrs") and the Peacock color/git blame: minor and croppable (bottom edge).

### (c) Failure-state / record-only images (not for the listing)
- **#18 (7.12.48)**: a docked browser tab window and a floating window both showing the same page at the same time; possibly a duplicate-window or stale-window state (not certain from the image).
- **#20 (7.26.51)**: opening a second file while a floating window was focused produced a *second* floating window ("HELLO WORLD! FILE 2."); looks like the lock-test outcome (QST-LOCK). Check against the ADR-0010 answer before drawing conclusions.
- **#19, #23**: Quick Open over a floating window, the interaction that led to #20 / the empty-editor state in #23 (the editor area is empty with the watermark, suggesting the file moved or closed).
- **#1, #3-#7**: Spike 0 step-by-step with the "All installed extensions are temporarily disabled" notification; useful as the spike's record (ADR-0003), not for users.
- **#14, #15**: mid-resize states with the command palette open; **#15** also captures a macOS screenshot thumbnail in the corner.
